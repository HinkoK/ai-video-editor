# Замер 1: как склеивать ролик по монтажному листу

2026-10-06. Синтетика, Apple M4, 16 ГБ, macOS 26.5, ffmpeg 8.1.

## Вывод

Берём **способ Б**: видео за один проход по оригиналу с выбором кадров по
номеру, звук отдельно с точностью до отсчёта, сжатие одно, в конце.
Способ А (каждый кусок отдельно и склейка) отклонён: кадры у него верные,
а звук уезжает от картинки.

## Что сравнивали

**А. Куски и склейка.** На каждый кусок `ffmpeg -ss начало -i src -t длина`
с перекодированием, потом concat без перекодирования. Так обычно и пишут
скрипт монтажа. Код: `backend/scripts/naive_segments.py`.

**Б. Один проход.** Видео: `select` по номерам кадров, затем время кадров
выставляется заново (кадр N стоит на N / fps). Звук: WAV исходника режется
кодом на Python, куски копируются байт в байт, на стыках сведение 10 мс,
потом AAC один раз. Код: `backend/src/longform/render/`.

## Как проверяли

В каждый кадр синтетики вшит его номер двоичным кодом, звук — шум с известным
зерном. После рендера программа читает номер каждого кадра и для каждого
куска ищет, на сколько отсчётов сдвинут звук относительно положенного места.
Положенное место считается по фактическому положению шума в исходнике (его
меряем, а не берём из замысла: см. находки ниже).

Повторить: `cd backend && uv run python scripts/spike_render.py --fps 30000/1001 --cuts 200`

## Находки, которые пошли в код

1. **Начало звука нельзя брать из заголовка потока.** У AAC в начале 1024
   служебных отсчёта (21 мс). В одном файле контейнер велит их выбросить, в
   другом — нет, и тогда они звучат. Заголовок в обоих случаях говорит одно.
   Берём время первого раскодированного кадра (`probe._first_audio_time`).
2. **ffmpeg сам дублирует кадры**, если видео начинается позже звука и
   вывод идёт в формат с постоянной частотой. Проверщик прочитал 308 кадров
   из 300. Везде, где читаем кадры, стоит `-fps_mode passthrough`.
3. **Выражение select ломается на 101-м куске:** ffmpeg не разбирает
   вложенность глубже 100. Цепочка `between()+between()+…` заменена деревом
   поиска `if(lt(n, середина), …)`: глубина log2 от числа кусков, около
   дюжины сравнений на кадр. В замере работает на 601 куске. Отдельно
   проверено, что дерево такой глубины ffmpeg разбирает и на 3000 условиях.
4. **Заголовок mp4 по умолчанию считает время в миллисекундах** и округляет
   длину звука: при 29.97 терялось 16 отсчётов в конце. Ставим
   `-movie_timescale` = НОК шкалы видео и частоты звука.
5. **Задуманный сдвиг синтетики не равен фактическому:** ffmpeg при сборке
   файла сдвинул звук на 32 отсчёта от заказанного. Поэтому проверщик меряет
   положение шума, а не верит замыслу.
6. **Перемотка на полкадра раньше** оказалась не нужна ни для mp4, ни для mkv
   со временем в миллисекундах: ffmpeg округляет время перемотки к шкале
   потока так же, как округлено время кадров. Запас оставлен как страховка,
   нарочная поломка тестами не ловится.

## Чего этот замер не доказывает

- Скорость, память и диск на настоящей записи: нужен файл автора.
- Плавающую частоту кадров (запись экрана). Такие файлы сейчас честно
  отклоняются при чтении свойств.
- Склейку нескольких файлов подряд и перестановку кусков: `select` пропускает
  кадры только в порядке исходника. Перестановка пока отклоняется.
- Звук больше 16 бит: сейчас режется в 16 бит, для AAC на выходе это не
  слышно, но это потеря, если исходник 24-битный.

## Цена способа Б

Промежуточные WAV: исходный звук целиком и звук монтажа. Для часа стерео
48 кГц это около 690 МБ и до 690 МБ, вместе ~1,4 ГБ. Учитывается в проверке
места перед рендером. Позже звук монтажа можно подавать в ffmpeg трубой,
без файла.
