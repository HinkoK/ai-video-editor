# Как устроено

## Схема

    Браузер (frontend/) ──HTTP, cookie──┐
                                        ├─► api.py ─► store.py / jobs.py / qa.py / asset_data.py ─► SQLite
    Claude Code ──MCP stdio──► agent/mcp_server.py ──HTTP, ключ агента──┘
                                                 worker.py ◄── очередь задач в SQLite
                                                    └─► render/, analysis.py, transcribe.py ─► ffmpeg, whisper-cli
                                                    └─► graphics/ (Chrome без окна) ─► кадры графики с прозрачностью

Сервер слушает только `127.0.0.1`. У автора и у Claude разные ключи с разными правами (CLAUDE.md, «Безопасность»).

Путь одной правки (режим «сразу», по умолчанию):

    Claude: look (кадры паузы) → propose_edit (MCP, ссылки A1#12 / A1#12.3-5 / A1~5)
      → api: фразы/слова → диапазон по речи
      → store.create_proposal: выравнивание по тишине → кадры → проверки → риски
      → _auto_apply: всё, кроме задевающего жёсткую защиту, сразу становится версией
    Автор: вкладка «Проверка» → до/после → оставить / вернуть как было / применить отложенное
      → store.review_op: новая версия, история сохраняется
    Экспорт: worker → render → verify → qa

Перестановка: Claude `propose_move` (только по указанию автора) или
автор на таймлайне ⌘X → курсор → ⌘⇧V → правка `move` отдельным
предложением → те же выравнивание, проверки и режим «сразу»; «вернуть как
было» в проверке — правка `unmove`.

## Время

Это фундамент, от него зависит всё остальное.

- Время исходника — целые микросекунды от первого показываемого кадра видео
  этого файла, а не от начала контейнера.
- Время монтажа — целые кадры выходного ролика, частота — точная дробь
  (например `30000/1001`).
- Звук — целые отсчёты; позиция кадра считается от нуля по сетке выходных
  кадров, а не суммой длительностей кусков. Ошибка округления не копится: на
  каждом стыке она меньше половины отсчёта.
- Интервалы полуоткрытые `[начало, конец)`. Никакого float в арифметике
  времени.
- Модель не считает время. Claude называет, что убрать (номера фраз и слов),
  границу ставит сервер: подтягивает к тишине, выравнивает по кадру и
  оставляет запас, чтобы не съесть начало слова (`analysis.PAD_US` = 70 мс).
- Начало звука — время первого раскодированного кадра, не заголовок потока.
- Точная перемотка ffmpeg оставляет кадр, НАЧАВШИЙСЯ после времени: чтобы
  получить кадр, видимый в момент, перематывать на полкадра раньше его
  начала.
- whisper.cpp: DTW (`-dtw`) работает только с `-nfa`; `--vad` сдвигает время
  токенов, с DTW его не включать.

## Запись с двух устройств

- Ведущий файл — запись экрана с микрофоном: в нём речь, по нему расшифровка
  и все правки по времени. Камера — ведомый файл: её картинка берётся в
  нужный момент по смещению, её звук нужен только для синхронизации.
- Монтажный лист режет время ведущего файла. Поверх него — **слой кадра**
  (что видно: экран, лицо, экран с лицом в углу, экран в рамке с лицом сбоку,
  крупный план, свои кадры, шторка) и **слой графики**. Оба привязаны ко
  времени исходника, как комментарии, и переживают правки чистки.
- Устройства идут на разных часах: синхронизация — смещение и скорость
  (замер в начале, середине и конце), а не одно число.
- Файлы разных частот и размеров: выходной кадр собирается по времени
  (какой кадр источника виден в момент выходного кадра).
- Камера может делить запись на несколько файлов — каждый сводится отдельно.

## Редакторский слой

Монтажный лист отвечает на вопрос «что исполнить». Редакторский слой — «почему
так можно и кто это разрешил». Всё ниже держит сервер, а не текст в промпте.

**Бриф ролика.** Для кого, что зритель поймёт или сможет сделать, обещание
названия, жанр, режим, что обязательно сохранить, что нельзя менять.
Хранится с проектом, у брифа есть версия. Claude может предложить черновик по
расшифровке, но черновик помечен как черновик, пока автор его не подтвердит.
Пустые поля не заполняются догадками.

**Защищённые фрагменты.** Жёсткая защита ставится автором: диапазон исходника и
причина; правка, которая её задевает, не проходит пакетом и требует
отдельного подтверждения с причиной. Мягкая защита ставится кодом:
фразы с отрицаниями и ограничителями («не», «нет», «без», «но», «только»,
«кроме», «если»), числами, деньгами и единицами. Это не запрет, а пометка
риска на правке. Пометка грубая: лишние срабатывания допустимы, пропуск
недопустим.

**Предложение правок.** Каждая операция несёт: проход (сейчас только
чистка), id базовой версии, якоря на фразы и диапазоны исходника, причину из
списка, короткое «почему», пометки риска, версию регламента. Причины:
неудачный дубль (с указанием, какой дубль оставлен вместо него), фальстарт,
пауза перед повтором, техническая пауза, подготовка записи, ожидание,
кашель (`vocal_noise`). Причина «другое» допускается только с объяснением и
всегда считается рискованной. Операции: убрать диапазон, вернуть диапазон,
переставить кусок (`move`) и снять перестановку (`unmove`); сдвиг границы
выражается через «убрать» и «вернуть».

**Перестановка кусков** — только по прямому указанию автора. Версия — оставленные
кадры каждого файла (`clips_json`, единственная правда для сборки) плюс
упорядоченный слой перестановок (`revisions.moves_json`). Запись слоя:
`{op_id, asset_id, src_start_us, src_end_us, target_asset_id,
target_src_us, side}` — «все оставленные кадры файла из [начало, конец)
идут подряд сразу после кадра, который кончается в target_src_us»
(`after`), или «перед кадром, который в этот момент начинается»
(`before`). Место привязано ко времени исходника, как комментарии, поэтому
перестановка переживает следующие вырезы, возвраты, сдвиги стыков и
частичное принятие: вырез внутри куска остаётся в нём, возврат внутри
куска — в кусок, снаружи — на своё место. `ops.layout` раскладывает версию:
оставленные интервалы по порядку файлов, затем перестановки по очереди
(кусок вынимается, разрезая соседей, и встаёт у якоря: после куска с
кадром P−1; если P−1 вырезан — после оставленного куска того же файла с
наибольшим концом ≤ P; иначе перед первым куском файла; `before` —
зеркально), соседние встык склеиваются; id куска — `файл@начало`, как
раньше. «Вернуть как было» (`unmove`) снимает запись своей правки — без
других правок следом версия ровно прежняя. Одна перестановка — одно
предложение без вырезов (`move_alone`); ошибки `nothing_to_move`,
`move_into_itself`, `move_nowhere`, `move_sliver` (кусок короче двух кадров
на границе), пока только внутри одного файла записи
(`move_between_files`). Пометки: `reorder` у каждой (поштучно, применение
не блокирует), `protected` — жёсткая защита в куске или место режет
защищённое (тогда ждёт автора), `cut_in_speech` по трём границам,
`splits_graphic` — граница режет графику. Границы: начало куска — перед
речью с запасом, конец — после, место «после фразы» — после её речи;
край оставленного интервала ближе 0,3 с без речи между — граница встаёт
на стык (`MOVE_SNAP_US`), иначе остаётся огрызок тишины. У ручной правки
автора (precise) — только защита от огрызка короче двух кадров. Лишнюю
тишину на месте, откуда взят кусок, сервер не режет — это отдельная
правка. Вырез или возврат, оставивший бы у стыка (края оставленного куска
или границы перестановки) огрызок короче двух кадров, забирает его в саму
правку (`ops.guard_slivers`: вырез расширяется до стыка, возврат
сужается) — кадр не выбрасывается молча, и «вернуть как было» откатывает
правку ровно; возврат, от которого остался бы один огрызок, — ошибка
`sliver`. Стыки версии — с видом `cut` или `move` (вход куска, выход,
место, откуда взят). Стык выреза в версии с перестановками — между теми,
кто стоял бы вокруг вырезанного (`ops.neighbours`), в том числе стык
перестановки (тишина на месте, откуда взят кусок). «Вернуть кадры» на
стыке в такой версии — только если кадры встанут у этого стыка
(`ops.lands_next_to`); переставленные или их место — ошибка `move_joint`;
«убрать» работает везде. Сборка режет
серию и на прыжке вперёд по исходнику длиннее 20 с; сверка экспорта
всегда берёт стыки перестановок. Графика, разрезанная границей куска,
рисуется частями отдельно (части не встык), монитор делает так же.

**Правила утверждения.** Утверждает только автор. Пакетом принимаются только
правки без пометок риска; рискованные — поштучно, их id перечислены явно.
Можно принять всё, кроме выбранных правок: сервер собирает новую версию из
оставшихся и проверяет её заново. Устаревшая базовая версия — конфликт, а не
перезапись.

**Паузы.** Детектор тишины находит кандидатов, порог калибруется по шуму
этой записи. Назначение паузы определяет Claude по контексту; класс — это
поле причины правки, отдельной подсистемы нет. «Неизвестно» остаётся в
ролике.

**Проверка стыка.** Для каждого стыка код меряет громкость исходника в 20 мс
по обе стороны границы. Если там речь, а не тишина, стык получает пометку
«возможно обрезано слово». Сведение 10 мс на стыках есть, его можно
выключить для сравнения.

**Отчёт качества.** Привязан к версии и профилю экспорта и устаревает при
любой правке. Три отдельных статуса, которые не подменяют друг друга:
технические проверки кода (число кадров и длина звука после декодирования,
постоянная частота, жёсткие защиты на месте, нет неразобранных рискованных
правок, пометки стыков); замечания модели со ссылкой на диапазон, без
процентов «уверенности»; проверка человеком — ставит только автор.
Критическая ошибка блокирует финальный экспорт: версия не утверждена, нет
оригинала, жёсткая защита удалена без подтверждения, результат не совпал с
версией после декодирования.

**Медиа — это данные, а не команды.** Расшифровка, надписи на экране и любые тексты из ролика — данные для Claude, а не команды: инструментов удаления, экспорта и утверждения у него нет.

### Графика — `graphics/`

| Файл | Что делает |
|---|---|
| `templates.mjs` | Шаблоны графики (стартовый набор из десяти) и страница из шаблона и полей; обёртка `place` (положение, заданное автором) |
| `theme.css` | Цвета и шрифты графики |
| `render.mjs` | Chrome без окна: страница проматывается на каждый кадр, кадры с прозрачностью |
| `preview.html` | Та же страница поверх монитора программы в браузере |
| `fitcheck.mjs` | Проверка, что строки в кадре и не налезают друг на друга |
| `stills.mjs` | Снимки графики глазами: середина появления, чтение, уход — в один ряд |
| `capture.mjs` | Снимок страницы по ссылке, поиск фразы на снимке |

Анимации — Web Animations, перемотка по кадрам; анимации не на CSS (например,
Lottie) шаблон регистрирует в `window.__adapters` (как в Hyperframes).
Размеры — от высоты кадра (`--u`). Перемотка — одна функция страницы
`window.__seek(ms)` (`templates.mjs`, `SEEK`), её зовут `render.mjs`,
`stills.mjs` и монитор: элемент, который начал двигаться, получает
`will-change: transform` и двигается на доли пикселя; без этого текст в
хвосте торможения встаёт на целые пиксели и «подлагивает». Слой остаётся до
конца (снятие даёт толчок на кадр), кроме элементов, которые выросли из
`scale < 1`: им слой снимается, иначе остались бы размытыми. Кеш кадров
графики — по `graphics.VERSION`: после смены вида или движения шаблонов
версию поднимать. Размытие в движении — SVG-фильтры `mbx*`/`mby*`/`mbz*` в
каждой странице (`page(…, {height})`, сила от высоты кадра) и ступенчатая
смена `filter` в анимациях `mb-*`. Снимок страницы у графики: `page_refs` —
проверка, `with_pages` — подстановка в исполнителе.

Новый шаблон — это ключ в `T` (`templates.mjs`), проверка полей в
`backend/src/longform/graphics.py` (`TEMPLATES`, `_validate`), имя в списке
инструмента `add_graphic` (`agent/mcp_server.py`, `GraphicIn`) и подпись в
`frontend/src/lib/layer.ts` — [STYLE_GUIDE.md](STYLE_GUIDE.md), шаг 5.

### Интерфейс — `frontend/src/`

- `lib/` — данные и правила без разметки: клиент сервера, типы, время,
  очередь проверки, геометрия кадра (`layout.ts` = `render/compose.py`),
  время камеры (`camera.ts`), ручной монтаж и клавиши (`edit.ts`), дорожки
  таймлайна (`tracks.ts`).
- `screens/` — Проверка, Расшифровка, Таймлайн, Монитор программы, Задачи,
  Экспорт, Проект.
- `components/` — общие элементы: значки задач, плеер со шкалой, списки.
- `styles/` — дизайн автора: токены, общие элементы, каркас, экраны. Как
  менять оформление, не трогая логику, — [design-handoff.md](design-handoff.md).

### Монитор программы

- Монитор — холст: на нём кадр собирается так же, как в `render/compose.py`
  (те же размеры раскладок, `frontend/src/lib/layout.ts`), из лёгких копий
  экрана и камеры. Время камеры — по сведению (`lib/camera.ts`).
- Графика поверх — окно `graphics/preview.html`: собирает ту же страницу, что
  `graphics/render.mjs` для кадров ролика, и проматывает анимации на момент
  курсора. Сервер отдаёт из `graphics/` только шаблоны, тему и шрифты — список
  в `api.py` (`graphics_file`). Новый файл, который импортируют шаблоны,
  добавлять в этот список: иначе в мониторе не грузится ни одна графика. Тест
  `test_graphics_files_for_the_monitor` проверяет все импорты.
- Положение: у участка кадра — `face {x, y, size}` и `card {x, y, w}` (доли
  кадра), у графики — `place {x, y, scale}`; правит только автор
  (`PATCH /visual/{id}`, `PATCH /graphics/{id}`, раскладка проекта).
- Тот же монитор — в окнах «До» и «После» экрана проверки
  (`review/FrameMonitor.tsx`, режим `bare` — только кадр): окно вокруг правки
  в своей версии (вырез — версия до правки и после, `lib/frames.ts`), правка
  кадра или графики выключается или включается поверх решения автора; полоса,
  J K L и «Текст вокруг» — через `PlayerHandle`, как у плеера.
- Текст графики правится в строке с ▶ и временем.
- Курсор во время просмотра: цикл просмотра (`requestAnimationFrame`) каждый
  кадр пишет время видео в курсор. Курсор, пришедший снаружи (тянут мышью),
  отличается от последнего сообщённого (`reported`) — цикл перескакивает
  туда и играет дальше; на кусок другой записи — останавливается там.
  Курсор в ref обновляется в `useLayoutEffect`, до следующего кадра
  просмотра, иначе цикл затирает его старым временем.

## Модель данных

SQLite, файл в рабочей папке. Главное: проекты, исходники (assets) с ролями
(экран — main, камера — camera), версии (неизменны), предложения и правки с
причинами и рисками, бриф, защита, комментарии и метки, задачи, расшифровка,
громкость и паузы, сведение камеры, слой кадра, графика, снимки страниц,
найденные звуки кашля, слой перестановок версии. Миграции —
`backend/src/longform/migrations/` (001–017: 011 — раскладка side и звук
камеры, 012 — снимки страниц, 013–015 — кашель, 016 — свои кадры, 017 —
перестановка кусков: правки move/unmove с местом, `revisions.moves_json`,
триггер неизменности версий с ним).

## Правила, которые держит код

- Время в целых единицах — тесты `test_timebase.py`, `test_edl.py` (случайные
  монтажные листы с фиксированным зерном, туда и обратно).
- Точность склейки доказывается раскодированным результатом (номера кадров в
  картинке и сдвиг звука, `tests/media_fixtures.py`), а не кодом возврата
  ffmpeg.
- ffmpeg запускается списком аргументов, без оболочки (`longform.ffmpeg`).
- SQLite-соединение — одно на запрос, `check_same_thread=False`: FastAPI
  открывает его и выполняет обработчик в разных потоках (ошибку нашёл живой
  браузер, есть тест).
- Модели ввода API (`Literal` раскладок и шаблонов) обновляются вместе с
  раскладками и шаблонами — однажды забыли, тест добавлен.
- Комментарии привязаны ко времени исходника: вырезанное место помечается
  «не входит в версию», а не переносится на соседний кусок.

## Находки и грабли

- **OBS пишет метки времени с дрожью** (1/50 кадра) — это не плавающая
  частота; допуск — четверть кадра.
- **Оценка места на диске** завышалась в 30–100 раз — теперь по пробному
  кодированию.
- **Whisper выдумывает на тишине** («Субтитры сделал DimaTorzok»,
  «Продолжение следует…») и **пропускает речь** — помечаются и
  перечитываются; **склеивает одинаковые дубли в одну фразу** — монтажу
  нужна нарезка по паузам и отдельная расшифровка частей.
- **Сплошная речь помечалась «нет речи»** — исправлено правилом пересечения.
- **Сервер считает вдох внутри фразы речью**: обычная правка на такой паузе
  отклоняется («нечего вырезать») — нужна точная правка (`precise`), у неё
  пометка «граница в речи», хотя громкость там на 18 дБ ниже голоса.
- **Сервер не даёт вырезать часть оставленного дубля** той же правкой, где
  этот дубль указан как оставленный (`alternative_removed`) — паузы внутри
  дублей отдельным предложением после вырезов.
- **Экспорт со слоем кадра падал** (ffmpeg: код −9, кончилась память) — сборка
  по участкам и склейка без перекодирования (`render/select.py`,
  `_render_by_shots`).
- **Графика во весь кадр давала лишние кадры и плавающую частоту** (Chrome
  сохраняет сплошные кадры без прозрачности) — кадры рисунка приводятся к
  одному формату.
- **Видео-фон, растянутый повтором кадров, дёргается сам** (21 к/с, доведённые
  до 30 повтором кадра): повторы убрать и поставить кадры на ровную сетку.
  Дорисовка до 60 к/с (minterpolate) не годится. Сборка ставит время кадров
  фона и своих кадров на их сетку (`select._clip_input`).
- **Камера по USB как картридер** может медленно отдавать файл и отваливаться
  каждые несколько минут, потом возвращаться сама; копировать кусками с повтором
  при обрыве. Сбой чтения может выбить один кадр без ошибки ffmpeg:
  проверять не только число кадров, но и ровный шаг времени.
- **Аппаратное декодирование (videotoolbox) файла камеры теряет кадры** —
  только программное. Кодировать можно аппаратно.
- **Поиск «кхм» вплотную к фразе** находит звуки, где Whisper в одиночку
  слышит «Продолжение следует…»; проверять расшифровкой куска с вырезом и
  без.
- **Экспорт читает раскладку проекта в момент сборки**: если двигать экран на
  мониторе во время экспорта, часть ролика соберётся по старому положению.
- **Задержки фильтров FFmpeg** (afftdn 1200 отсчётов, firequalizer 480,
  alimiter 239) сдвигают звук от губ — компенсировать и проверять сдвигом.
- **Сверка звука по ненормированной корреляции врала на голосе**: максимум тянулся к более громкому месту исходника на период
  основного тона — ложные 3,75 мс на стыке перестановки, где на 48 кГц
  сдвиг 0 и сходство 1,0. Корреляция в `verify._lag` нормируется на
  громкость окна исходника при каждом сдвиге.

## Ограничения и сознательно отложенное

- Плавающая частота у ведущего файла отклоняется при подключении. Дрожь
  меток времени до четверти кадра допускается. Камера может быть другой
  частоты и размера.
- Время слов — по DTW whisper.cpp, на синтетике в пределах 0,3 с от начала
  речи; на голосе автора подробно не сверено.
- Пробный ролик — не длиннее 120 с; весь ролик — только экспортом.
- В пробном ролике с середины участка подвод приближения экрана (`zoom`) и
  опускание слайда (`drop`) начинаются заново с начала пробы; движение
  камеры — как в готовом ролике.
- Монитор программы рисует кадр по лёгким копиям (540p): шторки, плавный
  наезд, подвод приближения экрана и размытие фона — упрощённо; точный кадр
  — в пробном ролике и экспорте. Лицо и экран нельзя вытащить за край кадра.
- Кадры на дорожке видео — примерно, до полсекунды (опорные кадры лёгкой
  копии); без лёгкой копии дорожка пустая.
- Ручной монтаж на таймлайне: отмена (⌘Z) помнит правки только пока открыта
  страница; после перезагрузки — откат версии в «Проверке». Удаление всегда
  со сдвигом. Растянуть край куска (вернуть вырезанное мышью) пока нельзя.
- Перестановка — только клавишами (⌘X, ⌘⇧V) и через MCP:
  перетаскивания мышью нет, сдвинуть край перестановки нельзя (вернуть и
  переставить заново), одна перестановка — отдельное предложение, без
  вырезов; между файлами записи не переставляется; копирования кусков нет
  и не будет. Графика на границе куска не переносится под новую границу —
  части рисуются отдельно, Claude получает предупреждение.
- Громкость камеры сервер не измеряет: на таймлайне вместо волны камеры —
  волна записи экрана.
- Кашель ищется по записи экрана: громкий звук 0,1–0,7 с без слов,
  перечитанный Whisper отдельно; и «кхм» вплотную к фразе — всплеск
  0,1–0,5 с, отделённый от речи провалами тише речи на 20 дБ от 60 мс. Кашель
  поверх слова и тихие звуки не ловятся. Поиск идёт только по оставленному в
  версии (±1 с): Claude зовёт `list_noises` после чистки.
- Если «кхм» стоял в начале куска сразу после прошлой склейки, стык после
  выреза бывает тесным (меньше 0,1 с): тишину возвращать только примыкающую
  к оставленному куску, иначе огрызок в несколько кадров.
- Длительность графики сервер меряет по времени записи: графику через
  склейку, за которой вырезано больше минуты, он не примет — конец ставить
  до склейки.
- Частота готового ролика — частота записи экрана.
- Громкость — одно усиление без ограничителя пиков: тихую запись с громкими
  пиками до −16 LUFS не дотянуть.
- Звук режется в 16 бит.
- Монтажёр не может отозвать свой непроверенный участок кадра или графику —
  «вернуть» может только автор.
